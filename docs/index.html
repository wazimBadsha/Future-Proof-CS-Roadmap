The learning model

AI changes how software is produced. It does not remove the need to understand systems, verify behavior, secure capabilities or own production outcomes.

Learn → Build → Test → Measure → Use AI → Verify → Red-team → Ship → Observe → Improve

Advanced CS and engineering tracks

These tracks fill deeper theoretical, systems and AI engineering gaps. They are selectable specializations, not mandatory prerequisites for every software role.

K — Discrete mathematics

Logic, proofs, relations, counting, probability, graphs and recurrences.

L — Theory of computation

Automata, grammars, computability, reductions and complexity.

M — Compilers and languages

Parsing, type systems, intermediate representations, runtimes and VMs.

N — Parallel and GPU computing

Concurrency, memory hierarchy, SIMD, OpenMP, CUDA and multi-GPU systems.

O — Foundation-model engineering

Transformers, post-training, PEFT, quantization, multimodal systems and inference serving.

P — Data engineering

Batch/stream processing, data contracts, lakehouse and ML data governance.

Q — Formal methods

Invariants, temporal properties, TLA+, Alloy and model checking.

R — Embedded and edge systems

Firmware, real-time constraints, device security and on-device inference.

S — Human-centered engineering

Accessibility, usability, localization, privacy and engineering ethics.

Every track defines prerequisites, labs, deliverables and measurable exit gates in the detailed curriculum.

How learning is assessed

Explain

Describe the model, assumptions and trade-offs without relying on generated answers.

Implement

Build a minimal artifact, experiment or formal model.

Test

Cover normal, boundary, adversarial and failure cases.

Measure

Collect correctness, performance, quality or usability evidence.

Transfer

Solve a changed problem without seeing the original solution.

Defend

Explain limitations and what the evidence does not prove.
